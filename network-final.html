ARP และ RARP: แปลงระหว่าง IP กับ MAC

ARP

รู้ IP → หา MAC (Layer 3 → Layer 2) กำหนดใน RFC 826 ส่งในเฟรม Ethernet โดยตรง Type = 0x0806

  • ARP query ส่งแบบ broadcast ช่อง Target MAC เป็น 00:00:00:00:00:00
  • ARP response ตอบแบบ unicast กลับหาผู้ถาม
  • ได้แล้วเก็บ <IP, MAC> ใน ARP cache ดูด้วย arp -a
RARP

รู้ MAC → ขอ IP ใช้กับ diskless workstation Operation = 3 (request), 4 (reply)

  • ทำงานที่ Data link ข้าม router ไม่ได้ ต้องมี RARP server ทุก subnet
  • admin ต้องจับคู่ MAC–IP เอง ไม่ใช่ autoconfiguration
  • จึงพัฒนาเป็น BOOTP แล้วเป็น DHCP

18.4 Subnetting

ยืมบิตจากส่วน host มาเป็นส่วน subnet: <network><บิตที่ยืม><host ที่เหลือ> บิต 1 ใน mask = ส่วนเน็ตเวิร์ก/ซับเน็ต บิต 0 = ส่วนโฮสต์

สูตร
  • จำนวน subnet = 2s (s = บิตที่ยืม)
  • โฮสต์ต่อ subnet = 2h − 2 (h = บิต host ที่เหลือ)
  • Block size = 256 − ค่า mask ในไบต์ที่ไม่ใช่ 255/0 เช่น /26 → 256 − 192 = 64 → subnet เริ่มที่ .0 .64 .128 .192
  • ตัวอย่างหนังสือ: 192.202.18.0/24 ยืม 1 บิต → mask 255.255.255.128 ได้ subnet 0 (.0–.127) และ subnet 1 (.128–.255)

18.5 CIDR และ Supernetting

CIDR เลิกคิดเป็นคลาส ใช้ prefix length แทน (/n) และรวมหลายเน็ตเวิร์กเป็น entry เดียว (supernetting / route aggregation) ลดปัญหา routing table explosion ตรงข้ามกับ subnetting ที่ทำให้ prefix ยาวขึ้น

ตัวอย่างหนังสือ

องค์กรได้ 192.12.240.0 ถึง 192.12.255.0 (16 คลาส C) ไบต์ที่ 3 คือ 1111 0000 ถึง 1111 1111 สี่บิตแรกคงที่ จึงรวมเป็น 192.12.240.0/20 (mask 255.255.240.0) ประกาศ entry เดียว

ถ้า 192.12.250.0/24 ถูกให้องค์กรอื่นไป แพ็กเก็ตไป 192.12.250.8 จะตรงทั้ง /20 และ /24 router เลือก /24 เพราะ prefix ยาวกว่า (longest prefix match)

18.6 เทียบ incoming IP กับ routing table ข้อ 2

  1. เอา IP ปลายทาง AND กับ mask ของแต่ละ entry
  2. ถ้าผลเท่ากับ network ของ entry นั้น = ตรง (match)
  3. ถ้าตรงหลาย entry ให้เลือก prefix ยาวที่สุด (เจาะจงที่สุด)
  4. ไม่ตรงเลย ใช้ default route 0.0.0.0/0 ถ้าไม่มี default ให้ทิ้งแพ็กเก็ตและส่ง ICMP Destination Unreachable (type 3)
ทางลัดตอนสอบ

TCP Sliding Window, RTT/Timeout และ Congestion Control

Sliding window

TCP ทำงานแบบ byte-oriented หลักเดียวกับ Go-Back-N/Selective Repeat ข้อมูลในบัฟเฟอร์ผู้ส่งแบ่งเป็น: (1) ส่งแล้วได้ ACK แล้ว (2) ส่งแล้วรอ ACK (3) ส่งได้ทันทีเมื่อ window ขยับ ตัวอย่างหนังสือ: 20–25 ได้ ACK แล้ว, 26–32 รอ ACK เมื่อได้ ACK ของ 26 และ 27 window เลื่อนไปส่ง 33 และ 34

Flow control · rwnd

ผู้รับบอกว่าบัฟเฟอร์รับได้อีกเท่าไรในช่อง window ของ ACK ตัวอย่าง: rwnd 8 → ผู้รับช้าลด rwnd เป็น 3 → ผู้ส่งส่งแค่ 3 → ลดเหลือ 1 ลดได้จนถึง 0 (หยุดส่ง)

Congestion control · cwnd

ผู้ส่งประเมินเองว่าเครือข่ายรับไหวเท่าไร สัญญาณคือแพ็กเก็ตหาย (timeout หรือ dup ACK) ส่งได้จริง awnd = min(credit/rwnd, cwnd)

Bandwidth-delay product

window ที่ดีที่สุด ≈ bandwidth × RTT เช่น 100 Mbps × 5 ms = 512 kbit = 64 KB ทำให้ส่งต่อเนื่องเต็มท่อ window ใหญ่ไป throughput สูงแต่เสี่ยงหาย เล็กไปใช้เครือข่ายไม่คุ้ม

RTT และ Timeout ข้อ 10

สูตร (หนังสือ 27.2)

EstimatedRTT = (1 − α)·EstimatedRTT + α·SampleRTT   (α = 1/8 = 0.125)
DevRTT = (1 − β)·DevRTT + β·|SampleRTT − EstimatedRTT|   (β = 1/4 = 0.25)
TimeoutInterval = EstimatedRTT + 4·DevRTT

เรียกว่า Exponential Weighted Moving Average (EWMA) ค่าเก่ามีน้ำหนัก 7/8 ค่าใหม่ 1/8 จึงไม่แกว่งตามตัวอย่างเดียว

ทำมือ 1 รอบ

EstimatedRTT = 100 ms, DevRTT = 5 ms, SampleRTT ใหม่ = 106 ms

  1. Est = 0.875 × 100 + 0.125 × 106 = 87.5 + 13.25 = 100.75 ms
  2. Dev = 0.75 × 5 + 0.25 × |106 − 100.75| = 3.75 + 1.3125 = 5.0625 ms

Congestion collapse

ช่วงโหลดน้อย throughput เพิ่มตามโหลดเป็นเส้นตรง พอเครือข่ายแน่น แพ็กเก็ตหาย ทุกคนส่งซ้ำ ยิ่งแน่นขึ้นจน throughput ตกลงเกือบศูนย์ TCP จึงถือว่าแพ็กเก็ตหาย = เกิด congestion (เพราะความผิดพลาดของลิงก์มีน้อยกว่า 1%)

1

Slow start

เริ่ม cwnd = 1 MSS ได้ ACK ครบรอบ cwnd เพิ่มเป็น 2 เท่า (exponential) จนถึง ssthresh

2

Congestion avoidance

เมื่อ cwnd ≥ ssthresh เพิ่มทีละ 1 MSS ต่อ RTT (additive increase)

3

Fast retransmit

ได้ ACK เลขเดิมซ้ำ 3 ครั้ง ส่ง segment นั้นใหม่ทันทีไม่รอ timeout

4

Fast recovery

หลัง fast retransmit ลด cwnd เหลือครึ่ง (ไม่ลดเหลือ 1) แล้วเข้า congestion avoidance เลย

กราฟ cwnd: Slow start + threshold ข้อ 7

  1. เริ่ม cwnd = 1, ssthresh = ค่าที่โจทย์ให้ (หนังสือใช้ 65535 ไบต์)
  2. ทุกรอบ (RTT) ถ้า cwnd < ssthresh ให้ คูณ 2 (ไม่เกิน ssthresh) ถ้า ≥ ssthresh ให้ บวก 1
  3. เกิด timeout: ssthresh = cwnd/2, cwnd = 1 แล้ว slow start ใหม่
  4. เกิด 3 dup ACK: ssthresh = cwnd/2, cwnd = ssthresh (fast recovery) แล้วเพิ่มทีละ 1

IntServ + RSVP (per-flow)

  • จองทรัพยากรให้แต่ละ flow ล่วงหน้า service class: Guaranteed, Controlled-load, Best effort

  • เก็บสถานะแบบ soft state ต้องส่ง refresh เรื่อย ๆ · flowspec (Rspec + Tspec) และ filter spec
  • Reservation style: Wildcard filter (WF), Fixed filter (FF), Shared explicit (SE) และรวมคำขอได้ (merging)
  • ข้อเสีย: scalability router ต้องจำทุก flow

  • DS domain มี boundary node (ingress/egress ทำ traffic conditioning) และ interior node (ส่งต่อตาม PHB)
